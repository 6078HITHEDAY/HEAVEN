# HEAVEN

HEAVEN 是一个面向 3D 立方体空间判定的音乐游戏项目。项目目标是在立体空间中构建可演奏、可编辑、可扩展的音游体验，并逐步发展出配套谱面编辑器、Boss 战模式和自定义内容系统。

当前工程使用 Godot 4 搭建原型，已有启动界面、3D 开始界面、主菜单、设置页、关于页和选择页等基础模块。

## 核心概念

游戏主体围绕两个立方体展开：

- 外置立方体：边长为 `L`，作为主要判定空间。
- 中心立方体：边长为 `l`，且 `l << L`，作为交互核心与元素发射源。

玩家需要在音乐时间轴上处理从中心立方体发射到外置立方体表面的交互元素。判定不仅发生在平面 UI 上，也会受到三维空间坐标、旋转、缩放和相对变换的影响。

## 玩法系统

### 动态元素

交互元素从中心立方体表面生成，并向外置立方体表面投射。基础元素类型包括：

- Surface Tap：平面触控点。元素到达外立方体表面时生成小型立方体判定块。
- Edge Slide：线性触控条。沿外立方体棱边生成可滑动组件。
- Spatial Judge：空间判定体。触发时引发外立方体旋转、缩放或其他空间变换。

### 判定系统

判定系统需要支持静态与动态两种场景：

- 基础判定：元素到达外立方体表面时触发点击判定。
- 动态判定：当外立方体发生空间变换时，基于相对坐标进行判定。
- 精确度分级：支持 `Perfect`、`Great`、`Good`、`Miss` 等多级评分。

## Boss 战模式

Boss 战模式会在标准音游玩法上加入角色互动和战斗反馈：

- 中心立方体可替换为 Live2D 模型。
- 模型根据玩家表现产生表情、动作和状态变化。
- 特殊攻击动画可与空间判定区域联动。
- 系统支持血量与得分双轨制，使音乐表现和战斗结果同时影响关卡推进。

## 谱面编辑器目标

谱面编辑器是项目的核心工具链之一，目标是让谱师可以在三维空间和音乐时间轴上编辑完整关卡。

### 基础功能

- 三维时空坐标系：支持 `X`、`Y`、`Z` 轴与时间轴。
- 元素类型选择器：支持平面、线性、空间三类元素。
- 动态参数设置：支持速度、角度、旋转轴、生成面、目标面等参数。
- 实时预览系统：编辑过程中即时查看元素运动和判定位置。

### 高级功能

- 空间变换轨迹编辑器。
- Live2D 事件触发器。
- 多难度分层系统。
- BPM 自动对齐工具。

## 数据设计

谱面数据优先使用易读、易调试的 JSON 格式。在核心结构稳定后，可以根据性能需求引入自定义二进制格式。

建议谱面结构包含：

- 曲目信息：标题、作者、音频路径、BPM、Offset。
- 难度信息：难度名、等级、谱师、版本。
- 音符事件：时间、类型、起点、终点、速度、判定参数。
- 空间事件：时间、持续时间、旋转、缩放、位移、缓动曲线。
- Boss 事件：Live2D 动作、表情、攻击、血量变化、特殊判定区域。

## 技术方向

当前项目基于 Godot 4 原型开发。后续重点技术包括：

- 3D 空间坐标与立方体表面映射。
- 基于四元数的旋转和相对坐标判定。
- 音频时间轴与 BPM 网格同步。
- 可序列化的谱面数据结构。
- Live2D Cubism SDK 集成方案调研。
- 编辑器与游玩模式的数据共用。

## 当前开发阶段

项目当前处于 `阶段 1：核心玩法最小原型` 的初步实现阶段。

这一阶段的目标不是立即完成完整玩法，而是先把工程入口、场景流转、基础菜单和项目文档整理稳定，为后续立方体音游核心玩法打地基。

当前已有内容：

- Godot 4 项目基础配置。
- UI 系统：启动界面、3D 开始界面、主菜单、设置页、关于页、选择页。
- 音频总线配置与基础音量设置逻辑。
- UI 美术资源、字体资源、菜单音频和菜单 shader 资源。
- 最小 Surface Tap 原型：外置立方体、中心立方体、测试音符、基础时间轴、判定、分数、连击和反馈显示。

当前优先事项：

- 将硬编码测试音符迁移为 JSON 谱面加载。
- 加入测试歌曲与音频时间轴同步。
- 继续打磨 Surface Tap 的视觉反馈、输入方式和判定窗口。
- 为后续 Edge Slide、Spatial Judge 和谱面编辑器保留清晰边界。

## 开发阶段规划

### 阶段 0：概念原型与工程整理

目标：让现有 Godot 工程可以稳定启动、跳转、导出，并形成清晰的项目结构。

主要任务：

- 修复当前 Godot 工程中的场景跳转、导出配置和信号连接问题。
- 明确当前主入口、主菜单、游玩场景和设置页的关系。
- 删除、归档或标记旧版实验场景。
- 补充项目文档与开发路线。
- 建立基础命名规范和目录规范。

验收标准：

- 项目可以从启动界面进入主菜单。
- 主菜单可以正常进入选择页、设置页、关于页。
- Android 导出配置包含所有必要场景。
- README 能说明项目目标、当前状态和下一阶段任务。

### 阶段 1：核心玩法最小原型

目标：实现最小可玩的 3D 立方体音游循环。

主要任务：

- 创建外置立方体与中心立方体。
- 实现中心立方体向外立方体发射 Surface Tap。
- 建立基础时间轴，支持按时间生成音符。
- 实现 `Perfect`、`Great`、`Good`、`Miss` 判定。
- 显示基础分数、连击和判定反馈。

验收标准：

- 可以加载一段测试谱面。
- 音符能从中心立方体发射到外置立方体表面。
- 玩家输入能触发判定并显示结果。
- 一首短测试曲可以完整游玩。

### 阶段 2：谱面数据与加载系统

目标：把玩法从硬编码原型转为可读取谱面文件的系统。

主要任务：

- 定义第一版 JSON 谱面格式。
- 支持曲目信息、BPM、Offset、难度信息和音符事件。
- 支持 Surface Tap 的起点、目标面、时间和速度参数。
- 建立谱面加载器与基础错误提示。
- 准备示例谱面文件。

验收标准：

- 游戏可以从 JSON 文件读取谱面。
- 修改谱面文件后无需改代码即可改变音符节奏和位置。
- 谱面格式有基本文档和示例。

### 阶段 3：谱面编辑器基础版

目标：制作可以编辑 Surface Tap 的基础谱面编辑器。

主要任务：

- 创建编辑器主界面。
- 显示三维空间预览和时间轴。
- 支持添加、删除、移动 Surface Tap。
- 支持 BPM 网格和吸附。
- 支持保存与加载 JSON 谱面。

验收标准：

- 可以在编辑器中制作一段可玩的测试谱面。
- 编辑器保存的谱面可以被游玩模式直接读取。
- 预览画面与实际游玩中的音符位置基本一致。

### 阶段 4：高级元素与空间变换

目标：加入完整的立体玩法表达。

主要任务：

- 实现 Edge Slide。
- 实现 Spatial Judge。
- 支持外置立方体旋转、缩放和空间变换轨迹。
- 建立动态判定中的相对坐标转换。
- 在编辑器中加入空间变换轨迹编辑。

验收标准：

- 谱面可以包含点、线、空间变换三类事件。
- 空间变换时仍能稳定判定。
- 编辑器可以预览空间变换效果。

### 阶段 5：Boss 战与 Live2D 扩展

目标：把中心立方体替换或扩展为可互动 Boss 核心。

主要任务：

- 调研 Godot 与 Live2D Cubism SDK 的集成方式。
- 设计 Boss 事件数据结构。
- 实现血量与得分双轨制。
- 实现模型表情、动作和攻击事件触发。
- 将特殊攻击动画与空间判定区域联动。

验收标准：

- 可以在测试关卡中触发 Boss 动作和攻击事件。
- 玩家表现会影响分数与 Boss 血量。
- Boss 事件可通过谱面或事件文件配置。

### 阶段 6：内容扩展与模组系统

目标：让项目具备长期扩展能力。

主要任务：

- 支持自定义皮肤。
- 支持曲包和谱面包。
- 设计特殊判定规则插件接口。
- 调研动态难度调整算法。
- 整理开发者文档和内容制作规范。

验收标准：

- 外部内容可以按约定目录加入项目。
- 谱面、皮肤和 Boss 配置可以相对独立维护。
- 项目文档足够支持后续协作开发。

## 扩展性目标

项目后续应保留模组化能力：

- 自定义皮肤替换。
- 特殊判定规则插件。
- 动态难度调整算法。
- 自定义 Boss 行为与 Live2D 事件。

## 项目愿景

HEAVEN 的目标不是把传统下落式音游搬进 3D，而是让空间本身成为谱面的一部分。玩家面对的不只是音符，而是一个会旋转、变形、攻击和回应音乐的立方体舞台。
